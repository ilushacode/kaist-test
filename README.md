## О проекте

**КАИСТ** - это pet-проект, выросший из простой идеи: сделать расписание, которым **приятно пользоваться каждый день**. Без иниернета, без регистрации, без десятков лишних экранов. Только то, что действительно нужно студенту: где, когда и с кем у него следующая пара.

Приложение полностью работает в браузере, устанавливается на домашний экран телефона как обычное приложение и не требует ни сервера, ни аккаунта.

---

## Почему это удобно

### 📡 Работает без интернета

Расписание скачивается один раз и хранится прямо на устройстве. В метро, в лифте, на паре с плохим Wi-Fi - **КАИСТ** откроется мгновенно и покажет всё, что нужно. Обновления подтягиваются автоматически, когда сеть снова появляется, и остаются незаметными для тебя.

### 🎨 Простой и понятный дизайн

Никаких перегруженных меню и непонятных иконок. Всё, что делает приложение, - показывает твои пары крупно, чисто и по делу. Светлая и тёмная темы переключаются в один тап и подстраиваются под систему.

### ⭐ Несколько групп в избранном - и переключение одним кликом

Учишься на двух направлениях, помогаешь другу с чужой группы, следишь за расписанием своего потока? **Добавляй сколько угодно групп в избранное** и переключайся между ними **одним тапом** прямо из меню. Каждая группа помнит своё расписание отдельно - ничего не путается и не смешивается.

### 🧑‍🏫 Всё, что нужно, в одном месте

- **Расписание** с аудиториями, корпусами и типами занятий.
- **Преподаватели** - имя, кафедра, предметы у твоей группы.
- **Одногруппники** - список группы со старостой.
- **Экзамены** - чтобы не искать их по вузовским сайтам.

### 🦢 Немного души

Если пар нет - приложение честно об этом скажет и покажет гуся. Иногда с шуткой. Мелочь, а настроение поднимает.

## Как начать

1. Открой приложение по ссылке.
2. Установи его на устройство:
   - **iOS Safari** - «Поделиться» → «На экран "Домой"».
   - **Android Chrome** - меню ⋮ → «Установить приложение».
   - **Desktop Chrome / Edge** - иконка установки в адресной строке.
3. Введи номер своей группы - приложение подскажет подходящие.
4. Готово. Расписание уже у тебя, работает офлайн.

## Технические детали

> Раздел для разработчиков и тех, кому интересно, как это сделано.

### Архитектура

KAIST - **полностью клиентское приложение**. Расписание и экзамены - это статические JSON-файлы, которые обновляются по расписанию через **GitHub Actions** и раздаются с **GitHub Pages**. Данные о студентах подтягиваются из внешнего публичного API наших друзей - **[Group-Finder.ru](https://group-finder.ru)**.

```
┌──────────────────────┐       ┌───────────────────────────┐
│  GitHub Actions      │──────▶│  schedule.json            │
│  парсит сайт КАИ     │       │  exams.json               │
└──────────────────────┘       └───────────────────────────┘
                                             │
                                             ▼
                                  ┌───────────────────────┐
                                  │  GitHub Pages (SPA)   │
                                  │  React + Vite + PWA   │
                                  └───────────────────────┘
                                             │
                                             ▼
                                  ┌───────────────────────┐
                                  │  group-finder API     │
                                  │  (студенты группы)    │
                                  └───────────────────────┘
```

Такая схема даёт три ключевых преимущества:
- **Ноль затрат на инфраструктуру** - статика бесплатна.
- **Максимальная скорость** - CDN GitHub Pages раздаёт файлы из ближайшего региона.
- **Офлайн по умолчанию** - все данные лежат в браузере, сеть нужна только для обновлений.

### Кэширование и обновления

Клиент не перекачивает тяжёлые JSON-файлы при каждом запуске:

1. **Свежий кэш (TTL 30 минут).** Если файл скачан меньше 30 минут назад - берём из IndexedDB, сети не касаемся.
2. **Проверка обновлений по `contentHash`.** После истечения TTL делается лёгкий запрос; если хэш содержимого совпадает с сохранённым - файл не перекачивается.
3. **Скачивание.** Только если сервер сообщил об изменении - файл загружается полностью и снова кладётся в IndexedDB.

Та же логика применяется раздельно к `schedule.json` и `exams.json` - обновление одного не тянет за собой другое.

### Формат `schedule.json`

```jsonc
{
  "meta": {
    "contentHash": "SHA-256[:16] - меняется при изменении расписания",
    "updatedAt":   "2025-10-08T06:00:00Z",
    "groupsCount": 512,
    "lessonsCount": 24817,
    "failuresCount": 3
  },
  "groups": {
    "3439": [
      {
        "d":  1,                 // день недели (1..6)
        "t":  "09:00",           // время начала
        "s":  "Математический анализ",
        "k":  "лек",             // лек | пр | л.р.
        "p":  "ИВАНОВ И.И.",     // преподаватель
        "a":  "423",             // аудитория
        "b":  "3",               // корпус
        "u":  "Кафедра ПМИ",     // кафедра
        "ds": ["чет", "12.10"]   // даты: числа, "чет"/"нечет", "ДД.ММ", "ДД.ММ.ГГГГ"
      }
    ]
  }
}
```

### Конфигурация

Все ключевые параметры вынесены в `src/config.js` и могут быть переопределены через `.env`:

| Переменная | Назначение |
|---|---|
| `VITE_SCHEDULE_URL` | Адрес JSON с расписанием |
| `VITE_EXAMS_URL` | Адрес JSON с экзаменами |
| `VITE_GROUP_FINDER_URL` | Адрес API со студентами |
| `BOOTSTRAP_TIMEOUT_MS` | Таймаут загрузки при старте |
| `REQUEST_TIMEOUT_MS` | Таймаут обычных запросов |

### Что внутри интересного

- **Виртуализация ленты недель.** Список недель семестра рендерится через `@tanstack/react-virtual` - в DOM живут только видимые элементы, даже если до конца семестра сотни недель.
- **Оптимистичный офлайн.** Приложение отдаёт кэшированные данные сразу, а обновления докачивает в фоне - пользователь никогда не ждёт.
- **Единый источник правды.** Расписание и экзамены лежат в Zustand, а IndexedDB обеспечивает персистентность без ручной синхронизации.
- **Осознанная работа с отменой запросов.** Каждый сетевой вызов принимает `AbortSignal` - при переключении групп или уходе с экрана старый запрос корректно отменяется.
